eeg-llm · Local EEG analysis

Two apps to install.
Then double-click Start.

This guide works for the main project and the tester package. Docker Desktop runs the EEG app; Ollama runs its language model on your computer.

Allow 40 GB free disk for downloads and build space, plus your recordings. We recommend 16 GB RAM or more; 32 GB is preferable. The 14B model can be slow on 16 GB or CPU-only systems. Internet is needed for initial downloads (roughly 10 GB for the models, plus Docker and app dependencies).

1. Choose the right download

Windows with Intel or AMD processorWindows · x86_64 / AMD64Settings → System → About → System type
Windows with ARM / SnapdragonWindows · ArmSystem type says ARM-based processor

AMD64 means both Intel and AMD 64-bit processors. It does not mean you need an AMD graphics card.

Mac: Ollama currently requires macOS 14 or newer; Docker supports the current and two previous major macOS releases. Intel Macs run Ollama on the CPU. Windows: use a currently supported 64-bit Windows version and Docker's WSL 2 backend with Linux containers.

Windows ARM is a preview/test path: Docker labels its Arm build Early Access. Its desktop installer and Ollama integration have not been verified by this project on physical Windows ARM hardware. ARM64 container compatibility alone does not certify that setup.

2. Install and open Docker Desktop

Download Docker for Mac · Download Docker for Windows

  1. Choose the download for your chip above and run the installer. On Mac, drag Docker to Applications.
  2. Open Docker Desktop, complete its welcome screens, and wait until the engine is running. Installing it alone is not enough.
  3. On Windows, keep Use WSL 2 selected and use Linux containers. If Docker asks for WSL installation or an update, follow its instructions and restart Windows if requested. You do not need to work in an Ubuntu terminal.
Windows asks me to install/update WSL

Open PowerShell as Administrator. For a missing WSL installation run wsl --install; for an existing installation run wsl --update. Restart if prompted, then reopen Docker Desktop. Docker requires WSL 2.1.5 or later and hardware virtualization enabled. If this is a managed work computer, ask IT to enable these prerequisites.

3. Install and open Ollama

Download Ollama for your operating system

  1. Run the installer. On Mac, move Ollama to Applications.
  2. Open Ollama and complete setup. If asked to install its command-line tool, allow it.
  3. Leave Ollama running. You do not need to pick a model or download one manually; eeg-llm's Start launcher handles both required models.

Close any old setup terminal before the next step, so Windows sees the newly installed commands.

4. Extract the project, then double-click Start

  1. Download the tester ZIP supplied by the project owner (or use the repository's Code → Download ZIP). Extract the entire folder to a writable location such as Documents. On Windows use Extract All; do not launch from inside the ZIP.
  2. Inside the extracted folder, double-click Start eeg-llm.command on Mac, or Start eeg-llm.bat on Windows. A terminal window opens. No Git, Python, Homebrew, make, or compiler installation is needed.
  3. Keep the terminal open while it prepares the models and app. The first build can take 5–20 minutes or longer, plus download time. Repeated progress messages are normal.
  4. When checks pass, the browser opens the app at http://127.0.0.1:8001 (or your configured port). You can then close the terminal. The app keeps running in Docker Desktop.

Next time: open Docker Desktop and Ollama, then double-click the same Start file. Downloads are reused and changed app files are rebuilt using Docker's cache. To stop the app, click its Stop button in Docker Desktop.

Mac blocks the launcher or says permission denied

Only for a copy you trust: try opening it, then use System Settings → Privacy & Security → Open Anyway if macOS offers it. If executable permission was lost during transfer, open Terminal, type chmod +x (including a trailing space), drag Start eeg-llm.command into Terminal and press Enter. Then double-click it again. Do not disable system-wide security settings.

Windows blocks the script

The .bat file uses Windows PowerShell for this launcher only. If your organization blocks scripts, ask IT to approve the supplied launcher; do not change organization policies. Only use Run anyway in a Windows download warning after verifying the package came from the project owner.

5. Try your recording

Drop your EEG files into the chat, or put them in data-in beside the launcher and type /scope my-recording.set. Keep paired files together: .set + .fdt, or .vhdr + .eeg + .vmrk. Describe your analysis with /plan …, review it, then use /run.

Keep using the same extracted folder so saved state and recordings remain associated with it. If you run the main and tester projects at the same time, set APP_PORT=8011 in a file named .env beside the tester launcher to avoid a port conflict.

Connection troubleshooting

If Start stops, read the last error in the terminal. Fix it and double-click Start again; completed downloads are kept.

  • Docker unavailable: open Docker Desktop, finish welcome screens, wait for the engine. On Windows check WSL and Linux containers.
  • Ollama unavailable: open Ollama. If just installed, close the terminal and double-click Start again.
  • App container cannot reach Ollama: first check Ollama is running, VPN/firewall settings, and any custom OLLAMA_HOST in the project's .env. The default container address is http://host.docker.internal:11434.
  • Port already in use: stop the other eeg-llm in Docker Desktop, or put APP_PORT=8011 in .env. Start will open the correct port.
  • Build/download fails: check internet, free space and the error printed by Docker/Ollama. Retry Start; if it fails again, send the final error lines to the project owner.
Ollama works on the host, but its bind address prevents Docker access

Only apply this if the container connection check fails. It makes Ollama listen on all network interfaces: keep port 11434 blocked from untrusted networks by your firewall; do not forward it on your router. This setting is for the Ollama server, not the container's destination address.

macOS: quit Ollama from its menu, open Terminal and run:

launchctl setenv OLLAMA_HOST 0.0.0.0:11434
open -a Ollama

This launchctl setting may need repeating after logout/reboot. To undo: launchctl unsetenv OLLAMA_HOST, then quit and reopen Ollama.

Windows: search for “Edit environment variables for your account”. Under User variables create OLLAMA_HOST with value 0.0.0.0:11434. Save, quit Ollama from the tray, and reopen it from Start. To undo, remove that user variable and restart Ollama.

Linux: for the systemd service, run sudo systemctl edit ollama.service, add:

[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"

Then run sudo systemctl daemon-reload and sudo systemctl restart ollama. Ensure your firewall permits Docker's bridge connection while blocking untrusted clients.

Linux and advanced checks

Use Docker Engine with Compose v2 (AMD64 or ARM64), or a supported Docker Desktop installation, plus native Ollama. Run bash start-eeg-llm.sh from the extracted folder. Desktop double-click behavior varies by Linux file manager.

After setup, diagnostic-only checks: bash start-eeg-llm.sh --check on Mac/Linux, or powershell -File .\start-eeg-llm.ps1 -Check on Windows. Stop: the same commands with --stop / -Stop. Python checks run inside Docker.
